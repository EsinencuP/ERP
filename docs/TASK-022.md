# TASK-022 — Projects Overview

19 октября 2026. Выполнено.

## Результат

`/projects/overview`: карточки проектов, прогресс DONE / все Task, использование бюджета, руководитель и команда. Поиск по коду/названию/описанию, фильтр статуса, серверная пагинация по 12 проектов. `/projects` сохраняет Kanban/List TASK-021, прежний реестр остаётся в `/projects/documents`. Общая навигация связывает эти экраны. Карточки ведут к задачам и расходам выбранного проекта; из задач и расходов можно вернуться к его обзору.

Прогресс включает CANCELLED в знаменатель буквального done/total; количество отменённых показано отдельно. Пустой проект показывает 0 из 0 и 0%. Бюджет использует сумму связанных Expense за всё время в валюте проекта. Другие валюты перечисляются отдельно без FX, поступления по Invoice не считаются затратами. Копейки передаются строками, арифметика и округление процентов выполняются через BigInt; в Number переводится только ограниченная заливка 0–100%. При перерасходе процент может превышать 100%, полоса заполнена полностью, превышение выделено текстом и цветом. При нулевом бюджете отношение не вычисляется.

Для источника затрат выбран предложенный в ходе работы вариант Expense.projectId: исходное задание не определяло источник Budget usage. Команда выводится из руководителя и уникальных исполнителей всех задач, включая исторические назначения. Отдельный ручной реестр команды не добавлялся. Preview ограничен шестью участниками, полный диалог — 20 на страницу; руководитель идёт первым, неактивные участники отмечены явно.

Timeline реализован CSS Grid без библиотеки: календарные даты начала/окончания Project, включённый последний день, однодневные полосы, обрезание границами окна, выходные и текущий день. Нет вымышленных дат для проектов без полного периода. Окно ограничено 1–93 днями, по умолчанию шесть недель относительно сегодняшней даты Москвы. Календарная арифметика использует UTC-дни. Выбранное окно сохраняется при обновлении, поиске и пагинации; горизонтальная прокрутка и sticky названия ограничены самим timeline.

Общая Sheet/RHF/Zod форма создаёт и изменяет код, название, описание, статус, бюджет, валюту, руководителя и даты проекта. Проверяются порядок дат, активность нового руководителя, live membership/роль, workspace и captured version. READONLY читает, AGENT+ создают и изменяют. Запись и audit атомарны в Serializable, retry разрешён только после гарантированного P2034 rollback. При конфликте или неизвестном исходе форма блокирует повтор до обновления. Ctrl/Cmd+Enter сохраняет, Escape закрывает, фокус возвращается к доступному элементу.

## Миграция и совместимость

`20261019000600_project_expenses` добавляет nullable Expense.projectId, составной tenant FK `(projectId, workspaceId)` и индекс `(workspaceId, projectId, currency)`. Существующие расходы сохраняются без проекта. Expense create/edit получает общий RecordPicker; переход из проекта заранее выбирает его. Старый update payload без projectId сохраняет связь, явная пустая строка очищает её. Переименование/переназначение проекта не меняет P&L: сумма расходов учитывается там по прежней политике. Удаление связанных проектов ограничено FK.

Миграция применена только к изолированной локальной PostgreSQL 17.10. Все 11 миграций актуальны, schema diff пуст. Новых зависимостей нет.

- Через реальные HTTP/Auth.js/PostgreSQL проверены create/update, stale version, два конкурентных обновления, пять ролей, отзыв/смена live Membership, чужие идентификаторы и прямой cross-tenant FK. Сбой audit полностью откатывает project create/update и expense reassignment/amount/version. Временный constraint удалён.
- До миграции создан расход без нового поля; после миграции его ID/amount сохранились, projectId = null. Привязка, перенос, очистка и старый update без projectId проверены; P&L total/count не изменились при перемещении затрат.

- Одноразовые проверки календаря: високосный день, включённый последний день, одиночная дата, обе обрезанные границы, отсутствие дат/пересечения, неверный/обратный/>93 период, ровно 93 дня и смена дня Москвы.
