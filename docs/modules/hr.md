# Команда / HR

Ниже описан текущий Document-интерфейс. TASK-002 добавляет нормализованные Employee с self-relation manager и Leave: [database.md](database.md). Кадровые workflow и переход UI на эти таблицы остаются отдельными задачами.

DocType `Employee`: `title` — имя сотрудника, `subtitle` — должность/отдел, `email` — обязательный рабочий email, `amount` — зарплата в копейках, `date` — дата приёма, `notes`. Статусы: Работает, В отпуске, Неактивен.

Actions: `getEmployees`, `createEmployee`, `updateEmployee`, `deleteEmployee`. MANAGER не может удалять HR-записи; VIEWER не изменяет их. Стартовая политика разрешает всем трём ролям просмотр HR-полей. Перед реальными кадровыми данными нужно отдельное право на зарплаты и персональные сведения.

Сотрудник — бизнес-документ, не User для входа. Создание сотрудника не создаёт учётную запись. Payroll, отпуска с согласованием, кадровые документы и отдельная модель отделов не реализованы.
