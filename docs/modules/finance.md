# Финансы

Ниже описан действующий UI на Document/DocumentPayment. TASK-002 отдельно добавляет нормализованные Invoice/InvoiceItem/Payment, налоговые поля и уникальный номер внутри workspace: [database.md](database.md). Эти модели не подменяют текущие JSON-документы автоматически.

DocType `Invoice`: `title` — номер счёта, `subtitle` — клиент, `amount` — итог в копейках, `date` — оплатить до, `notes` — назначение. Номер счёта пока вводится вручную; глобальная/tenant-нумерация и уникальность номера — следующая задача.

Статусы: Черновик → Отправлен → Частично оплачен → Оплачен. Создание допускает только первые два. `createPayment` принимает положительную сумму в копейках и UUID-reference. Сервис запрещает оплату черновика, переплату, повтор reference и stale version. Поступление, смена статуса и audit event сохраняются атомарно. Статус определяется суммой поступлений.

После поступления нельзя изменить сумму, клиента и статус; удаление такого счёта запрещено. Номер, назначение и срок можно уточнить. Поступления показываются в форме оплаты для неоплаченного остатка и влияют на dashboard. Полная история всех платежей в отдельном реестре и возвраты — последующие задачи.

Actions: `getInvoices`, `createInvoice`, `updateInvoice`, `deleteInvoice`, `createPayment`. Валюта — RUB, значения целочисленные. Лимит одного платежа 20 млн ₽; итог документа до 10 млрд ₽. Модуль не заменяет бухгалтерский учёт: строки, налоги, проводки, банковская интеграция и кредит-ноты отсутствуют.
