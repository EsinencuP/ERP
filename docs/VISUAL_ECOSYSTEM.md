# Единая визуальная экосистема портфолио

Дата: 29.10.2026. Референс — предоставленные пользователем снимки Workspace в светлой и тёмной теме. Цвета крупных поверхностей и основных кнопок сняты непосредственно с PNG. Шрифт по снимкам достоверно не определяется; ERP сохраняет Geist Sans с кириллицей и Geist Mono.

## Готовое задание для переноса в другой проект

> Переведи существующий проект в визуальную экосистему Workspace/Evo. Сохрани структуру экранов, контент и поведение. Сначала проверь текущую дизайн-систему, затем введи общие семантические CSS-токены и привяжи к ним все компоненты.
>
> Светлая тема: тёплый молочный фон #F2F0EA, белые карточки #FFFFFF, вложенные поверхности #F4F2ED, текст #1C201E, вторичный текст #59695F, границы #CBD0C7, границы полей #7A8780. Основная кнопка и ссылки — глубокий зелёный #175449, текст кнопки белый, hover #103F36.
>
> Тёмная тема: фон #111614, карточки #1C211F, вложенные поверхности #252B28, основной текст #EDF2EE, вторичный текст #ADBDB5, границы #34423D, границы полей #65756E. Основная кнопка и ссылки — шалфейный #B8D4AD, текст кнопки #111614, hover #C8DEBF.
>
> Верхняя навигационная панель остаётся тёмной #121715 в обеих темах. Для её текста, кнопок и фокуса используй отдельные chrome-токены с контрастом тёмной темы.
>
> Типографика: Geist Sans, кириллица и латиница; Geist Mono для кодов и чисел. Основной текст 14px с line-height 1.5, подписи 11–12px, заголовки страниц 28–32px / 600 / line-height 1.25 / tracking -0.04em. Не уменьшай текст ради буквального совпадения с масштабированным скриншотом.
>
> Формы: тонкие границы 1px, скругления полей и кнопок 4px, карточек 4–6px, диалогов до 8px. Карточки плоские; мягкая тень допустима для всплывающих слоёв. Аватары и индикаторы могут быть круглыми. Основные кнопки однотонные, с весом текста 600. Активная навигация использует мягкий зелёный фон.
>
> Статусы успеха, предупреждения, ошибки и информации имеют собственные токены. Графики используют ту же систему и несколько различимых оттенков. Убери старые жёстко заданные цвета из компонентов и экспортируемых материалов. Сохрани заметный клавиатурный фокус, disabled/error/loading/empty states и поддержку reduced motion.
>
> Проверь обе темы на реальных экранах: навигация, таблица, Kanban, форма, диалог, график. Проверь ширины 1440px и 375px, отсутствие внешнего горизонтального переполнения, сохранение выбора темы и WCAG AA для текста. Не подменяй недоступные реальные данные демонстрационными.

Для верхней панели используется отдельное семейство `--color-chrome-*`. Оно одинаково в двух темах: фон #121715, поверхность #252B28, hover #303A34, границы #34423D / #65756E, текст #EDF2EE / #ADBDB5, акцент #B8D4AD и мягкий фон #29473C. Локальные aliases внутри `.shell-header` позволяют общим кнопкам и аватарам оставаться читаемыми в светлой теме.

Нейтральные разделители не заменяют контрастную границу интерактивного поля. Для полей используется `--input` → `--color-border-strong`. Текст на полупрозрачных статусах проверяется относительно фактической поверхности. Обозначение статуса всегда сохраняет текст, а где предусмотрено — иконку или точку.

## Порядок реализации

1. Найти текущие токены, общие Button/Card/Input/Table/Dialog, настройки шрифта и темы. Зафиксировать действующие размеры и сценарии.
2. Обновить центральную палитру; сохранить aliases библиотеки компонентов. Цвета статусов менять по смыслу, а не общей заменой всех зелёных или красных значений.
3. Настроить радиусы в теме UI-библиотеки, убрать декоративные тени карточек. Изменения не должны ломать круглые аватары, hit areas и прокрутку таблиц.
4. Сохранить или подключить Geist Sans/Mono с кириллицей, настроить иерархию заголовков. Не менять геометрию экранов без необходимости.
5. Проверить графики, уведомления, портальные меню и PDF/HTML, если они используют общие токены. Сохранять семантические различия категорий и статусов.
6. Выполнить production build и визуальную проверку обеих тем на desktop/mobile. Переключать тему штатной кнопкой, проверить сохранение после перезагрузки.
7. Зафиксировать фактические результаты и ограничения. Публикация и Git commit выполняются только в пределах запроса пользователя.

## Реализация в Evo ERP

- `globals.css`: тёплая светлая / зелёно-графитовая тёмная палитра, статусы, focus, графики, chrome, плоские panel и более плотные заголовки.
- `tailwind.config.ts`: общая шкала радиусов 2 / 4 / 6 / 8 / 12px; круглая форма не переопределяется.
- Общие `Button` / `Card`: текст действия 600 и карточки без декоративной тени.
- Geist, ThemeProvider, локализация, размеры контролов и бизнес-логика сохраняются. Новых зависимостей нет.
- Генерируемая `public/user-guide.html` получает палитру из CSS во время сборки; этот файл не редактируется вручную.
