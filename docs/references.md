# Референсы проекта

TASK-015: [modern-erp-nextjs](https://github.com/imranbru99/modern-erp-nextjs) — SKU/stock/reorder alerts и отдельные warehouses; [ERPNext Stock Level Report](https://docs.frappe.io/erpnext/stock-level-report) — остаток в конкретном warehouse; [Aureus ERP Inventories](https://github.com/aureuserp/aureuserp) — выделение каталога/складов. Конкретные формулы total/minStock/status и sidebar alert определены пользовательским заданием; код и новые версии стека референса не переносились.

TASK-016: [ERPNext Stock Entry](https://docs.frappe.io/erpnext/stock-entry) и [Stock Ledger](https://docs.frappe.io/erpnext/stock-ledger) — source/target warehouses, приход/списание/перенос и ledger с количеством и складом. Valuation/perpetual accounting, backdating, отмена/амендирование референса не копировались: в этом задании движения immutable, исправления — новые entries. Использованы Master Skill, webdev-api-data, webdev-crm-systems, webdev-frontend-craft; текущие проектные Prisma 6/Next 15 сохранены.

TASK-014: [ERPNext Accounting Reports / Financial Statements](https://docs.frappe.io/erpnext/accounting-reports) — сравнение доходов/расходов за период, согласованные company/date/currency filters и отделение P&L от cash flow. Пользовательская формула этого ERP использует именно fully paid invoices по дате окончательной оплаты, а не accrual ledger референса. Код не переносился. Применены Master Skill, webdev-api-data, webdev-crm-systems и webdev-frontend-craft; SQL/Route Handler/UI переиспользуют установленные Prisma 6/Next 15 и существующие проектные контракты. Страница `/erpnext/financial-statements` вернула 404; использована актуальная Accounting Reports.

Репозитории просмотрены как источники архитектурных и UI-направлений. Код из них не копировался. Список сохраняется для последующей работы; он не означает реализацию всех возможностей референсов.

API Next.js 15 и Prisma 6 сверены с первичными материалами через Context7. Локальные UI primitives следуют Radix/Shadcn-style композиции, адаптированы под CSS tokens и правила проекта.

TASK-001: [Shadcn CLI](https://ui.shadcn.com/docs/cli), [theming](https://ui.shadcn.com/docs/theming), [Sonner](https://ui.shadcn.com/docs/components/sonner), [Next.js Fonts](https://nextjs.org/docs/app/api-reference/components/font), [Auth.js installation](https://authjs.dev/getting-started/installation). TailAdmin используется как референс устройства Tailwind/layout, Open Mercato — как референс общего UI-слоя; конкретные шрифты и палитру определяет TASK-001 пользователя.

TASK-002: ERPNext — разделение бизнес-документов и строк счёта; Twenty — глобальный User и участие в Workspace; modern-erp-nextjs — журнал аудита. Конкретная схема проектная, код референсов не переносился. API миграций сверялся с установленным Prisma 6.19.3 и его version-specific материалами; актуальные Prisma 8 команды не применяются к этому проекту. Для фактической проверки миграции использована отдельная локальная PostgreSQL 17 из [embedded-postgres](https://github.com/leinelissen/embedded-postgres), установленная только в игнорируемый `.data`, без зависимости приложения и системной службы.

TASK-003: форматирование дат сверено через Context7 с первичными материалами date-fns: [Unicode tokens](https://github.com/date-fns/date-fns/blob/main/pkgs/core/docs/unicodeTokens.md), [локализация](https://github.com/date-fns/date-fns/blob/main/pkgs/core/docs/i18n.md). Для календарного года и дня месяца используются yyyy/dd; форматирование Date использует локальную timezone среды выполнения, существующий dateLabel сохраняет явно заданную Europe/Moscow.

TASK-004: [Auth.js Credentials](https://authjs.dev/getting-started/authentication/credentials), [RBAC JWT/session callbacks](https://authjs.dev/guides/role-based-access-control), [SessionProvider/useSession](https://authjs.dev/getting-started/session-management/get-session), [module augmentation](https://authjs.dev/getting-started/typescript). API сверены через Context7 и установленный next-auth 5.0.0-beta.32. Twenty используется как направление разделения глобального User и workspace Membership; конкретная матрица пяти ролей — политика этого ERP, а не копия политики Twenty. Применены локальные skills webdev-crm-systems и webdev-api-data: единая матрица, обязательная серверная проверка и изоляция tenant.

TASK-005: TailAdmin — разделение Sidebar/Header и responsive shell; Aureus ERP — группировка модульного меню по задачам. Код референсов не копировался. Жизненный цикл App Router layout/template сверён через Context7 с [Next.js 15 templates](https://github.com/vercel/next.js/blob/v15.1.8/docs/01-app/03-api-reference/03-file-conventions/template.mdx). Используются уже установленные Shadcn Sidebar/Sheet/Tooltip и next-themes, без новых зависимостей. Локальные keyframes названы component-enter, чтобы не перекрывать enter из tailwindcss-animate.

TASK-006: API транзакций проверен по [официальной документации Prisma ORM v6](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions): Serializable для записи, RepeatableRead для списка/count, version в условиях обновления. Context7 выдавал материалы Prisma 8 даже для запроса v6, поэтому они не использовались; контракт сверялся с version-specific документацией и установленным Prisma 6.19.3. CRM следует существующим направлениям ERPNext (отдельные сущности), Twenty (workspace Membership), modern-erp-nextjs (audit); код референсов не копировался.

TASK-007: [TanStack Table v8 row selection](https://tanstack.com/table/v8/docs/guide/row-selection), [v8 pagination](https://tanstack.com/table/v8/docs/guide/pagination). Использованы v8 useReactTable/getRowId/manualPagination/rowSelection, соответствующие установленному 8.21.3; Context7 main выдавал v9 примеры, поэтому контракт сверялся с официальными v8 страницами. Twenty — направление выбора записей по устойчивым идентификаторам и массовых действий, без переноса исходного кода. Конкретные границы выбора/экспорта, optimistic versions и tenant-проверки — политика этого ERP. Применены skills webdev-crm-systems, webdev-frontend-craft и webdev-api-data.

TASK-008: [Dnd Kit legacy Sortable](https://dndkit.com/legacy/presets/sortable/overview/), [DragOverlay](https://dndkit.com/legacy/api-documentation/draggable/drag-overlay/), [Keyboard Sensor](https://dndkit.com/legacy/api-documentation/sensors/keyboard/). Эти API соответствуют установленным @dnd-kit/core 6.3.1 и @dnd-kit/sortable 10.0.0. Современные @dnd-kit/react примеры из Context7 не переносились в legacy API. Использованы DndContext/SortableContext/useSortable, отдельная empty-column drop zone и визуальный-only overlay; keyboard coordinates адаптированы для перехода по этапам. Уровни вероятности — явная локальная политика по stage, не заимствованный прогноз и не новое поле БД. Применены skills webdev-crm-systems, webdev-frontend-craft, webdev-api-data.

TASK-009: [Twenty](https://github.com/twentyhq/twenty) — разделение record header, timeline и information sidebar; [Frappe FormTimeline](https://github.com/frappe/frappe/blob/develop/frappe/public/js/frappe/form/footer/form_timeline.js) — типизированные активности с иконками и chronological feed. Код не переносился. Dynamic params/revalidatePath сверены через Context7 с [Next.js 15 dynamic routes](https://github.com/vercel/next.js/blob/v15.1.8/docs/01-app/02-building-your-application/01-routing/10-dynamic-routes.mdx) и [revalidatePath](https://github.com/vercel/next.js/blob/v15.1.8/docs/01-app/03-api-reference/04-functions/revalidatePath.mdx). Сохраняются RHF/Zod, Prisma 6 и действующие workspace/RBAC правила.

TASK-010: применены skills webdev-crm-systems (формы создания/редактирования, inline validation при blur) и webdev-frontend-craft. API сверены через Context7 с [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog): modal=false, Content focus/outside/Escape callbacks; установленный Radix не рендерит Overlay в non-modal Root. [React Hook Form useForm](https://github.com/react-hook-form/documentation/blob/master/src/content/docs/useform.mdx) — mode/reValidateMode=onBlur, defaultValues, handleSubmit. Установленный Sonner используется через toast.success/error; общая палитра Toaster сохраняется. Автосохранение из примеров skill не включено: здесь явно подтверждаемая форма с Cmd/Ctrl+Enter и versioned Server Actions.


TASK-011: [IDURAR invoice management](https://github.com/idurar/idurar-erp-crm) — направление для invoice/items/payment workflow, без переноса исходного кода. API сверены через Context7 с первичной документацией [React-pdf Node API](https://react-pdf.org/node), [fonts](https://react-pdf.org/fonts), [page wrapping](https://react-pdf.org/advanced#page-wrapping). Применены renderToBuffer, локальный Font.register, fixed header/footer, wrap=false для ограниченных фрагментов строки. [Geist в Google Fonts](https://github.com/google/fonts/tree/main/ofl/geist) — источник TTF; OFL-лицензия сохранена рядом в public/fonts. Применены skills webdev-api-data, webdev-crm-systems и webdev-frontend-craft; серверная политика округления, RBAC и нумерация определены этим проектом.

TASK-012: [Aureus ERP](https://github.com/aureuserp/aureuserp) — разделение Accounting/Accounts/Payments; [ERPNext Accounts Receivables](https://docs.frappe.io/erpnext/accounts-receivables) — outstanding после оплат и aging по due date. Сроки/валюты и cash-based Revenue определены этим проектом; ledger референсов не копировался. Recharts 2.15.4 сверён через Context7 с [Accessibility](https://github.com/recharts/recharts/blob/v2.15.4/storybook/stories/API/Accessibility.mdx) и [ResponsiveContainer](https://github.com/recharts/recharts/blob/v2.15.4/storybook/stories/API/ResponsiveContainer.mdx). Donut реализован PieChart/Pie innerRadius, HorizontalBar — BarChart layout=vertical. LineChart accessibilityLayer поддерживает стрелки; для остальных графиков доступны текстовые данные. Применены skills webdev-api-data, webdev-crm-systems, webdev-frontend-craft, read-docs; код источников не переносился.

TASK-013: [Frappe HR Expense Claim](https://docs.frappe.io/hr/expense-claim) — expense date/type/amount и подтверждающие документы как ориентир декомпозиции. Employee reimbursement, approval workflow и бухгалтерские проводки не переносились: пользователь запросил отдельный Expense CRUD. Prisma enum/model/tenant relation сверены с [официальной v6 документацией Models](https://www.prisma.io/docs/orm/v6/prisma-schema/data-model/models) и установленным Prisma 6.19.3; смешанные Prisma 8 примеры Context7 не применялись. Формы следуют существующим RHF/Zod/non-modal Sheet; применены skills webdev-api-data, webdev-crm-systems, webdev-frontend-craft и read-docs. Код референсов не копировался.


TASK-017: применены действующие складские паттерны TASK-015/016 и skills webdev-api-data, webdev-crm-systems, webdev-frontend-craft. Границы KPI и формула стоимости определены заданием и моделью Product; повторно использован общий SQL CTE вместо отдельной трактовки остатков. PDF skill использован для read-only визуальной проверки checkpoint PDF через Poppler. Код внешних референсов не переносился.
